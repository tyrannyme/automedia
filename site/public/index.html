How it works

A web page with a clock.

Automedia seeks your document to every frame instead of recording it in real time. Slow scenes don't drop frames, and the same frame always renders the same pixels.

  1. 01

    Write a page

    A project is a folder of HTML, CSS, and JS. Draw with whatever the browser has: Canvas, SVG, WebGL, WebGPU, or plain CSS. 

    window.automedia.registerRenderer(
  ({ timeSeconds, frame, controls }) => {
    ball.style.translate =
      `${timeSeconds * 240}px 0`;
  },
);
  2. 02

    The clock drives it

    Headless Chromium renders each frame on a frame-based clock. CSS keyframes, Web Animations, Motion, and Three.js all land on the exact time.

  3. 03

    Export anything

    Video, stills, and audio encode in-process with Mediabunny. No FFmpeg to install. Validation runs the same renderer as export, so what passes is what ships.

For agents

Your agents write it. You watch it land.

Any number of agents share one engine over MCP. They create compositions, write files, validate, and queue exports. Exports are taken from each agent in turn, so one agent's batch never starves another's.

.mcp.json 
{
  "mcpServers": {
    "automedia": {
      "command": "automedia",
      "args": ["mcp"]
    }
  }
}

Build the command once from a checkout with pnpm build:cli, then pnpm link --global.

The studio

For the last ten percent.

The studio is a window onto the same engine. Scrub the timeline, nudge a control, edit the source, and export. Agents never need it open.
